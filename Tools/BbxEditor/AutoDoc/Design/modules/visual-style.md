# 统一视觉风格

## 1. 模块说明

BbxEditor 使用低饱和深灰色工具软件风格，目标是降低长时间编辑的视觉疲劳，同时保证 Timeline、行为树、节点类型选择与 Inspector 的层级清晰。视觉资源集中在 `src/BbxEditor.Wpf/Themes/GrayTheme.xaml`；页面和动态控件应引用语义化资源，不应自行复制颜色值。

## 2. 主题色板

| 语义 | 资源名 | 色值 | 用途 |
| --- | --- | --- | --- |
| 应用背景 | `AppBackgroundBrush` | `#232528` | 窗口底色、行为树外层背景 |
| 工作区背景 | `WorkspaceBackgroundBrush` | `#292C30` | 编辑器内容区 |
| 侧栏背景 | `SidebarBackgroundBrush` | `#26282C` | Inspector、标签栏和紧凑辅助区 |
| 基础表面 | `SurfaceBrush` | `#303338` | 卡片、工具栏、菜单和配置区 |
| 抬升表面 | `SurfaceRaisedBrush` | `#383C42` | 输入控件、弹出菜单与抬升内容 |
| 悬停表面 | `SurfaceHoverBrush` | `#41464D` | 鼠标悬停 |
| 按下表面 | `SurfacePressedBrush` | `#4A5058` | 按下或展开状态 |
| 基础边框 | `BorderBrush` | `#4A4F56` | 卡片、分隔线和控件边界 |
| 强边框 | `BorderStrongBrush` | `#626972` | 浮层、窗口外框和高层级边界 |

## 3. 形状、字体与间距

- 标准控件圆角为 `6`，面板、卡片、浮层和窗口圆角为 `8`。
- 普通控件最小高度为 `30`；图标按钮通常为 `30 × 30`。
- 页面外边距使用 `12`、`14` 或 `20`，卡片内边距使用 `10` 或 `14`，相邻紧凑控件间距使用 `2` 到 `7`。
- 默认字体为 `Segoe UI`，正文大小为 `13`；区域标题为 `16/SemiBold`，页面标题为 `22/SemiBold`，辅助说明为 `10` 到 `11`。
- 整个应用界面仅使用英文；菜单、按钮、标题、工具提示、空状态、状态栏、确认框、错误消息和校验诊断不得出现中文或中英混排。
- 主要信息使用主文字色，解释信息使用次文字色，类型、协议提示和占位说明使用弱文字色。
- 拖拽对象必须使用圆角外形，并通过光标变化、悬停提亮、选中边框或拖拽手柄至少提供两种可感知反馈。

## 4. 控件状态

- 普通按钮使用抬升表面；悬停切换为悬停表面，按下切换为按下表面，键盘焦点使用强调边框。
- 主操作使用强调色底和深色文字；删除等危险操作使用透明底与危险文字，仅在悬停时显示危险色背景。
- TextBox 和 ComboBox 默认使用基础表面，悬停增强边框，获得焦点后使用强调边框与抬升表面。
- ListBoxItem、TabItem 和编辑卡片使用柔和强调背景与强调边框表示选中。
- 禁用控件保持原语义颜色但透明度降至约 `0.42–0.45`，并取消手型光标。
- Timeline 的有限区间使用蓝灰色，无限区间使用低饱和危险色；右端始终保留缩放手柄，悬停和选中时增强对比度。
- 行为树普通节点使用中性灰，Condition 节点使用灰绿色；选中、连接源和拖动状态使用不同边框色，避免只依靠填充色区分。

## 5. 窗口、菜单与浮层

- 主窗口和所有派生 Window 必须显式应用 `{StaticResource {x:Type Window}}`，并覆盖完整客户区，禁止露出系统默认白底。
- 配置等次级窗口使用灰色自绘标题栏、强边框、可滚动内容区和固定底部操作栏；缩小到最小尺寸时操作按钮仍必须完整可见。
- MenuItem 模板必须把 `Foreground` 显式传给 Header；Popup 是独立视觉树，Popup 容器和关键子菜单项都必须显式设置 `TextPrimaryBrush`，不能只依赖继承。
- 弹出菜单使用抬升表面、强边框和 `7–8` 圆角；悬停与展开分别使用悬停表面和按下表面。
- 节点类型选择窗口使用与配置窗口一致的自绘标题栏和固定底部操作栏；候选列表必须同时展示名称、类型、标签与说明，选中态使用柔和强调背景和强调边框。
- 对话框、下拉框和菜单不得出现纯白背景、纯黑文字或系统默认蓝色高亮。

## 6. 实现与维护

标准 WPF 控件样式统一维护在 `GrayTheme.xaml`。Timeline 与行为树的自绘色板分别维护在 `TimelineOverviewControl` 和 `BehaviorTreeCanvas`，其色相和状态规则必须与本规范一致。Inspector 动态生成的控件通过应用资源名称读取画刷和样式。

视觉改动完成后至少验证 Debug/Release XAML 编译和发布版窗口启动；涉及 Window、ContextMenu、MenuItem、ComboBox 或 Popup 时，还应实际打开对应浮层检查背景、文字、裁切和焦点状态。界面文字改动还必须扫描 `src/`，确认不存在中文字符；Unity 元数据提供的业务名称和说明属于外部内容，不在界面语言约束的翻译范围内。
