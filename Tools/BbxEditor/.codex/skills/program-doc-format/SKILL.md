# Program Doc Format

本 skill 用于编写或更新 `AutoDoc/Program/` 下的程序文档。本项目不是游戏项目，不预设游戏模块、UI 或 GameStage 等分类。

程序文档分为两类：

1. 项目总文档：简短说明这是个什么项目、有哪些系统和主要功能。
2. 普通文档：记录一个独立模块的实现信息。

## 基本规则

1. 使用用户的语言编写文档。
2. 文档路径和文件名必须使用英文。
3. 普通文档每篇只记录一个独立模块。
4. 文档篇幅不要太长；当发现单篇文档过长、包含多个独立职责，或阅读维护成本明显升高时，可以主动拆分为多篇模块文档。
5. 同一文件夹下文档数量不要超过 10 篇；超过时自动拆分进不同英文子文件夹。

## 路径规则

1. 程序文档统一放在 `AutoDoc/Program/` 下。
2. 项目总文档固定路径为 `AutoDoc/Program/project-overview.md`。
3. 普通文档推荐使用英文子目录承载。
4. 当需要进一步分组时，使用英文分组目录。

## 项目总文档

项目总文档不使用普通文档的固定章节。

项目总文档应保持简短，主要说明：

1. 这是一个什么项目。
2. 项目包含哪些系统。
3. 项目的主要功能。

次要功能和细分功能不需要写在项目总文档里，应放到对应普通模块文档中。

## 普通文档固定章节

每篇普通文档必须包含且仅包含以下章节。如果对应章节没有内容，也保留章节标题，并将内容写为“暂无”。

## 1. 模块说明

说明该模块的职责、边界和主要用途。

## 2. 对外接口

记录该模块暴露给其他模块、用户界面、命令行、网络、脚本或配置入口调用的接口。

## 3. 调用链路

梳理该模块从入口到核心逻辑执行的主要调用链路。

## 4. 数据来源

记录该模块读取、写入或依赖的数据来源，例如配置文件、数据库、外部服务、缓存、本地文件、运行时状态等。

## 5. 与其他模块的依赖

记录该模块依赖的其他模块，以及其他模块对本模块的依赖关系。
