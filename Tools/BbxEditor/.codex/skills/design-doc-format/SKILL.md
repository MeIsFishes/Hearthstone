# Design Doc Format

本 skill 用于编写或更新 `AutoDoc/Design/` 下的设计文档。

程序文档分为两类：

1. 项目总文档：简短说明这是个什么项目、有哪些系统和主要功能。
2. 普通文档：记录一个独立模块的实现信息。

## 基本规则

1. 使用用户的语言编写文档。
2. 文档路径和文件名必须使用英文。
3. 普通文档每篇只记录一个独立模块。
4. 文档篇幅不要太长；当发现单篇文档过长、包含多个独立职责，或阅读维护成本明显升高时，可以主动拆分为多篇模块文档。
5. 同一文件夹下文档数量不要超过 10 篇；超过时自动拆分进不同英文子文件夹。

## 路径规则

1. 设计文档统一放在 `AutoDoc/Design/` 下。
2. 项目总文档固定路径为 `AutoDoc/Design/project-overview.md`。
3. 普通文档推荐使用英文子目录承载。
4. 当需要进一步分组时，使用英文分组目录。

## 项目总文档

项目总文档不使用普通文档的固定章节。

项目总文档应保持简短，主要说明：

1. 这是一个什么项目。
2. 项目包含哪些系统。
3. 项目的主要功能。

次要功能和细分功能不需要写在项目总文档里，应放到对应普通模块文档中。

## 普通文档

每篇普通文档可以参考包含以下内容：

1. 模块说明：说明该模块的职责、边界和主要用途。
2. UI 交互：记录该模块的 UI 交互、用户操作流程和界面变化。
3. 数据来源：记录该模块读取、写入或依赖的数据来源，例如配置文件、数据库、外部服务、缓存、本地文件、运行时状态等。
4. 其他必要的章节。
