# BGM 接入任务检查清单

- [ ] 确认 `Resources/BGM` 下的实际音频资源名称、格式与加载路径，不创建、编辑或删除 `.meta` 文件。
- [ ] 梳理项目现有音频框架，以及大厅、备战、战斗、胜利、失败的生命周期和状态切换入口。
- [ ] 大厅与备战播放 `Lobby` BGM，战斗播放 `Battle1` BGM。
- [ ] 胜利与失败分别播放对应 BGM；从战斗 BGM 切换时使用 0.5 秒切换时间。
- [ ] 胜利/失败 BGM 播放完毕后停止，且不自动播放新的 BGM。
- [ ] 在既有音频底层中扩展可配置的 BGM 淡入淡出时间，保持已有调用兼容，并明确零时长及重复切换行为。
- [ ] 检查并处理场景/Stage 重入、重复请求、协程或异步竞态、对象生命周期与资源释放等直接依赖。
- [ ] 框架边界审计：复用项目已有公开 API、生命周期、资源加载与音频管理能力；若存在最小且向后兼容的能力缺口，在框架内扩展并回归验证，不保留业务层平行实现。
- [ ] 代码质量审计：新增字段与函数具有实际复用价值，不引入不必要的一次性抽象或额外 GC。
- [ ] 验证修改仅覆盖相关文件，并执行可用的静态检查、测试或编译检查；按项目约定默认不启动 Unity 游戏验证。
- [ ] 玩家视角设计文档：完整读取基础格式 skill，核对实际玩家可见变化、现有相关文档、处理结论、目标路径与证据。
- [ ] 美术文档：完整读取基础格式 skill，核对音频资源相关现状、现有相关文档、处理结论、目标路径与证据。
- [ ] 程序文档：完整读取基础格式 skill，核对音频底层/API 与状态接入的实际变化、现有相关文档、处理结论、目标路径与证据。
- [ ] 结束前逐项复核并写入证据；只运行一次 `AutoDoc/CleanupTempDocs.bat`，随后创建对应任务报告。
