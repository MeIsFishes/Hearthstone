# 怪物词条策划案任务检查清单

## 任务分类

- [ ] 类型：编写正式策划案。
- [ ] 目标：为当前五类怪物建立词条规则、卡牌说明区展示规则与融合继承规则，并形成可供后续实现与流程日志验收的正式策划案。
- [ ] 用户指定优先级：P1。
- [ ] 用户指定验收方式：流程log验收。
- [ ] 用户指定实现方式建议：每次攻击和受击时开启一个 Task，在 Task 中实现词条效果；仅写入可选第七章，不作为技术定案。

## 需求拆分说明与意见

### 真实需求摘要

玩家需要在战斗前从卡牌说明区清楚识别怪物的特殊能力，并在战斗中获得稳定、可预期的目标选择、伤害结算、范围影响、团队成长和融合继承反馈，使不同怪物拥有明确定位，同时让融合后的能力组合可理解、可追踪。

### 需求分块

| 功能点 | 所属模块 | 游戏场景 | 依赖或耦合 | 是否可独立设计和验收 |
| --- | --- | --- | --- | --- |
| 怪物词条与卡牌说明区展示 | 卡牌展示/战斗单位 | 查看怪物卡牌、确认战场单位能力 | 是所有词条行为的玩家信息入口；与融合后的多词条展示直接耦合 | 可局部验收，但必须与词条规则共同设计以避免文案与行为分离 |
| 嘲讽目标优先规则 | 战斗目标选择 | 敌方发起攻击 | 影响所有攻击者的合法目标集合 | 可独立验收 |
| 远射伤害与反伤规则 | 战斗伤害结算 | 哥布林弓箭手攻击 | 与基础攻击伤害取整、反伤触发边界耦合 | 可独立验收 |
| 爆裂范围伤害规则 | 战斗范围与伤害结算 | 哥布林投弹手命中目标 | 依赖“周围一格”空间定义、主目标与溅射目标区分 | 可独立验收 |
| 冲锋团队增益规则 | 战斗攻击触发/属性变化 | 野猪发起攻击 | 与攻击成立时点、我方单位范围和持续时间耦合 | 可独立验收 |
| 食人魔无词条基线 | 怪物配置/卡牌展示 | 查看及使用食人魔 | 作为无特殊能力的对照组 | 可独立验收 |
| 融合词条汇集与去重 | 卡牌融合/战斗单位生成 | 多张素材卡融合 | 强依赖词条定义与卡牌说明区的多词条展示 | 可独立验收，但规则与展示必须共同说明 |

### 文档建议

- [ ] 建议创建 1 篇策划案：`怪物战斗词条与融合继承`，英文文件名 `monster-combat-keywords.md`，归档路径 `AutoDoc/DesignPlan/2026.08.15/monster-combat-keywords.md`，优先级 `P1`。
- [ ] 优先级理由：词条直接影响核心战斗决策和怪物差异化，也涉及已有怪物、攻击结算、目标选择与融合等多个高频流程；但未被描述为阻塞游戏运行的最高紧急缺陷，采用用户指定的 P1。
- [ ] 覆盖范围：五类怪物的初始词条、卡牌说明区展示、嘲讽/远射/爆裂/冲锋规则、无词条基线、融合汇集及同名词条去重。
- [ ] 范围边界：不扩展新怪物、新词条等级、词条叠层、数值平衡体系、动画音效重制或完整技术实施 Plan。

### 拆分与合并理由

- [ ] 合并理由：所有规则共同服务于“怪物通过可见词条形成战斗定位”这一玩家目标，发生在连续的卡牌查看—攻击结算—融合产物查看流程中；融合继承又必须引用同一套词条定义与展示规范，拆篇会造成规则重复和验收链路割裂。
- [ ] 不另拆 UI 篇：说明区仅承载词条名称与效果文本，不构成独立界面目标，可作为词条系统的必要玩家反馈共同设计。
- [ ] 不另拆融合篇：本次只规定词条的并集继承与去重，不重新设计融合配方、属性公式或融合流程。

### 主代理意见与合理假设

- [ ] “周围一格”暂按以主目标所在格为中心、距离一格内的其他敌方单位理解；主目标不重复受到爆裂的半额伤害，具体格制邻接形态须在文档中明确为待现有战场格制解释，不擅自引入新格制。
- [ ] “远射造成一半伤害”按该次攻击原本将造成的伤害乘以 50% 后向下取整；最低值不另行保底，因此攻击值为 1 时可造成 0 点伤害。
- [ ] “不会受到反伤”仅免除由本次攻击直接引起的反伤，不免除敌方主动攻击、范围伤害或其他非反伤伤害。
- [ ] “冲锋”按每次野猪实际发起一次攻击时触发一次，增益包含攻击者自身和当时仍在场的所有友方单位，效果为本场战斗内持续；若后续规则要求临时增益，应另行修订。
- [ ] 多个嘲讽单位存在时，每次需要选择攻击目标均从当时存活且可被攻击的嘲讽单位中随机；若没有可被攻击的嘲讽单位，沿用常规目标选择。
- [ ] 融合产物显示全部去重后的词条；食人魔作为素材不贡献词条；词条顺序需稳定，暂按融合素材顺序收集、同名首次出现保留。
- [ ] 用户同时提出多个效果，但它们属于同一词条系统的强关联规则集合，故采用一篇策划案；未来新增通用词条编辑、词条等级或大规模 UI 改版时应另立策划案。
