# 核心战斗系统方案——已确认需求稿

> 状态：用户已于 2026-08-14 确认。本稿是完整 Plan 的需求输入。

## 1. 需求明确

### 1.1 需求对齐

1. 进入战斗 StageGroup 后自动开始一场战斗，不要求玩家点击、拖拽或选择目标。
2. 我方与敌方各生成 3 张卡牌，初始槽位固定为从左到右 1、2、3 号位。
3. 每张卡牌固定为 5 点最大生命、3 点攻击，即“5 血 3 攻”。
4. 一次行动只由一张牌发起攻击。我方先行动，之后敌我严格交替。
5. 双方分别维护攻击游标：本方每次行动从游标位置向右寻找第一张存活牌，越过 3 号位后回到 1 号位；攻击完成后游标移到该攻击者的下一槽位。
6. 死亡牌立即退出攻击序列与索敌候选，后续行动直接跳过，不改变其余牌的原始槽位。
7. 攻击者从对方当前所有存活牌中等概率随机选择一个目标。
8. 攻击采用同时伤害：目标失去攻击者的攻击力，攻击者同时失去目标的攻击力；双方伤害使用结算开始时的面板值。
9. 伤害后生命降至 0 的牌立即死亡。一次攻击的伤害、死亡与胜负判断完成后，才切换行动方。
10. 任意一方无存活牌时立即结束：敌方空场判我方胜利；否则我方空场判敌方胜利。若同一次互击令双方同时空场，按已确认的“判胜”解释为我方胜利，不设置平局结果。
11. 战斗结束后停止攻击循环并保留最终场面，显示“我方胜利”或“敌方胜利”。
12. 每场战斗保存一个非零随机种子，所有随机索敌沿用同一随机序列，保证记录种子后可复现。
13. 第一阶段采用最小占位表现：敌我两排卡牌、攻击/当前生命、行动方、攻击者/目标高亮和最终结果；不加入复杂攻击动画。

### 1.2 本轮范围外

1. 卡牌技能、关键词、种族、星级、护盾、嘲讽、风怒、复生、召唤与亡语。
2. 战斗中手动选目标、拖拽、出牌、调整站位或暂停。
3. 玩家英雄、英雄生命、战后英雄伤害、奖励、酒馆购买和下一局流程。
4. 联机同步、存档、回放文件和完整数值配置表。
5. 正式角色原画、复杂位移动画、粒子特效和音效。

### 1.3 关键验收示例

1. 开局第一次行动必须由我方 1 号位发起；之后在双方均存活时依次为敌 1、我 2、敌 2、我 3、敌 3、我 1……。
2. 5 血 3 攻的双方互击后各剩 2 血，不会在第一击死亡。
3. 若轮到某方时游标所指牌已死亡，该方从该位置继续向右找到下一张存活牌；死亡牌不会补位或重新编号。
4. 随机目标只能来自对方存活牌；同一种子与相同状态产生相同目标序列和结果。
5. 最后一次互击令双方同时空场时，结果为我方胜利，且之后不再产生攻击。
