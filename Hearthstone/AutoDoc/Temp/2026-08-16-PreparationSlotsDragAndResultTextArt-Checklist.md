# 备战槽位、拖拽回牌库与结算文字美术检查清单

## 用户要求

- [ ] 重新核验实际运行 Prefab 与列表条目，真正缩小备战页面出战槽位，并让槽位之间出现清晰间隔。
- [ ] 卡牌从出战槽拖离且未落入其他合法槽位时，返回牌库，不再回弹到原出战槽。
- [ ] 使用生图功能生成黄色“已出战”透明文字资产，并替换当前难辨识的运行时文字/图标表现。
- [ ] 使用生图功能分别重新生成文字与底板一体的完整“胜利”横幅、“失败”弹窗和“大获全胜”弹窗素材；失败/全局胜利的固定提示语直接画入素材，只为独立重新开始按钮留位。
- [ ] 使用生图功能生成完整“返回主菜单”按钮资产，用图片替换现有程序色块、描边和文字 Label，并保持 Button 点击区域与交互状态可用。
- [ ] 最终五张资产（已出战、三个完整结算 UI、返回主菜单按钮）统一参考现有做旧羊皮纸、战场木板、UI 控件和卡片原画：整体介于陈旧羊皮纸与炉石式奇幻 UI 之间，避免圆润、厚倒角、塑料高光和卡通化。
- [ ] 三个结算 UI 可沿用最初辨识配色：普通胜利蓝金、失败暗红、全局胜利蓝金；通过降低饱和、增加旧羊皮纸/旧木磨损与轻油画笔触控制年代感。
- [ ] 结算按钮点击后使用项目现有流程返回主菜单，不再直接调用重新开始游戏。
- [ ] 将最终视觉基准、禁用特征、资产路径与接入规格写入美术总文档。

## imagegen 资产流程

- [ ] 使用 `view_image` 检查当前卡牌、结算 UI 和已有相关资产，确定字形、颜色、留白和接入尺寸。
- [ ] 使用内置 imagegen，按不同文字资产分别调用生成；所有中文必须逐字准确且仅出现一次。
- [ ] 逐张目检文字正确性、透明背景、边缘、可读性、无额外字符、无水印；不合格则定向重试。
- [ ] 将最终五张项目资产复制到 `Assets/Resources/Art/` 下对应模块目录，使用独立文件名；移除本任务已生成但被新方向淘汰的拆分结算文字草稿，不覆盖无关资产。
- [ ] 更新 Builder/Prefab/Controller 引用，并在最终报告记录每张资产路径、最终提示词和内置工具模式。

## UI 与框架边界

- [ ] Preparation/Battle 页面继续使用唯一 View/Controller；静态图片节点由一一对应 UiBuilder 维护并重建 Prefab。
- [ ] 动态卡牌继续使用既有 `UiList`、预加载映射和对象池，不在 Controller 中拼装静态页面或自行管理对象生命周期。
- [ ] 拖拽返回牌库优先通过现有拖拽事件和玩法公开入口实现，不复制 UiDragable 生命周期或直接操作框架内部池。
- [ ] 核对 UiScene Group、DefaultShow、整体位置/缩放/Pivot 是否变化；仅在导出信息变化时重新导出 UiSceneAsset。
- [ ] 不手写 Prefab/Scene/Asset YAML，不手工创建、编辑或删除 `.meta`，不覆盖或回退无关工作区改动。
- [ ] 检查新增函数、字段和资源引用是否必要，移除一次性或重复抽象。

## 验证与文档

- [ ] 用 Unity 结构/运行逻辑核验出战槽视觉宽度、列表中心距、可见空隙以及卡牌进入槽位后的等比缩放。
- [ ] 覆盖拖入出战槽、从出战槽拖回牌库/空白区域、换槽及非法拖放后的状态一致性。
- [ ] 核验“已出战”、三个完整结算 UI 与完整返回主菜单按钮由 ResourceApi/Builder 正确加载、Prefab 引用正确；旧标题/正文文字节点及按钮 Label 不再重叠显示。
- [ ] 覆盖失败与全局胜利弹窗点击“返回主菜单”的阶段切换、按钮禁用与页面关闭行为。

- [ ] 核验活动场景恢复且未脏；按项目约定不主动进入 Play Mode，并记录未执行的游戏内验证风险。

- [ ] 程序文档：读取适用格式 skill 与引用，同步槽位、拖拽和结算 UI 资源行为。
- [ ] 结束前重新读取本清单并逐项审计，标记通过、未通过或不适用并附证据。
