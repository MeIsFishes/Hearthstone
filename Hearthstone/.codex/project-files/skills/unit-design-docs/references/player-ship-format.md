# 我方舰船单位文档格式

我方舰船文档使用 `# <舰船展示名>` 作为标题，一篇只对应一艘我方舰船。正文严格使用以下 6 章，不增加其他编号章节，六章均必须保留。某章暂无可确认内容时明确记录当前未提供，不省略章节，也不根据策划案或未来构想补写。

## 1. 单位定位

- 说明该舰船当前实现所体现的设计思路，包括希望玩家形成的战斗节奏、操作重点、优势、弱点和与其他舰船的核心差异。
- 必须明确接敌方式是侧舷接敌、正面接敌还是混合接敌，并说明舰体朝向、主要武器射界、攻击面和玩家应保持的相对方位。
- 说明该接敌方式如何影响武器使用、防御压力和玩家决策；当前只有一艘舰船时也要独立说明，不虚构未来对照舰船。
- “设计思路”只总结当前已经落地的玩家体验，不记录尚未实现的方案或开发过程。

## 2. 外观与动画

- 描述舰船轮廓、朝向、相对体量、配色、舰桥、武器区、推进器、护盾和其他玩家可见结构。
- 按触发状态说明待机、出战、武器发射、冷却就绪、护盾受击或破裂、舰体受击、修复、击毁和离场动画；写清循环、持续和结束后的可见状态。
- 只记录玩家实际可见的画面与动画，不写源文件、Prefab、Clip、帧资源名或制作步骤。
- 可以在本章直接插入能说明当前外观、接敌方向或动画状态的图片。图片遵循项目媒体目录与相对路径规则，每张图附图注；没有有效当前图片时不放占位图。

## 3. 背景故事

- 记录当前项目已经确认、且玩家能够从名称、界面、剧情或其他正式内容中获知的舰船来历、所属、建造用途、服役经历和当前任务。
- 只保留与该舰船身份和玩家体验直接相关的设定，不扩写世界观总览，也不把其他舰船的故事并入本文。
- 当前没有可确认的背景故事时，明确写“当前项目未提供该舰船的背景故事”，不得根据外观、名称或策划案自行推断。

## 4. 基本属性

- 使用表格汇总当前舰体生命、护盾、受击范围、移动或固定方式、防御顺序、恢复规则和其他会影响玩家决策的基础属性。
- 每项包含“属性、当前值、玩家可感知含义”；不适用的属性明确写“不适用”，不杜撰数值。
- 说明受击、护盾消耗、舰体损伤、修复、失败和重开时属性如何变化或恢复。
- 不写配置字段、内部数据类型或运行时存储方式。

## 5. 武器列表

- 使用表格列出该舰船当前装载的全部武器；每项至少包含“武器名称、安装位置/射向、有效输入、攻击特点、伤害与关键节奏”。
- 说明每种武器的发射位置、瞄准或索敌方式、射界、弹道、命中反馈、冷却，以及它如何服务侧舷或正面接敌。
- 多个键位使用完全相同武器和规则时可以合并一行，但必须完整列出有效键位；禁用键位与无法发射状态也要明确。
- 通用武器机制可以链接战斗系统文档，本章必须保留该舰船实际装载与舰船专属差异。

## 6. 强化线路

- 按线路列出当前对该舰船生效的强化节点、解锁顺序、前置条件、分支、互斥、消耗和最终效果。
- 说明强化如何改变基本属性、武器、输入节奏或接敌方式，以及玩家在界面中看到的解锁、撤回和生效反馈。
- 全舰共享强化可以链接共享强化文档，但必须说明它在本舰上的当前装载和实际效果。
- 当前没有可确认的强化线路时，明确写“当前项目未提供该舰船的强化线路”，不得用未来规划或其他舰船线路填充。
