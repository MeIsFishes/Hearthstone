# 敌机单位文档格式

敌机文档使用 `# <敌机展示名>` 作为标题，一篇只对应一种敌机。正文严格使用以下 7 章，不增加其他编号章节；前 6 章必须保留，只有第 7 章在该敌机没有实质状态转换时可以整体省略。

## 1. 单位定位

- 说明该敌机在战斗中的职责、主要威胁、优势、弱点和最明显的辨识特点。
- 说明玩家面对它时的核心判断与应对方向，以及它和其他敌机最关键的体验差异。
- 只写当前已实现的定位，不使用未来敌机或未实现能力作为对照。

## 2. 外观与动画（可附图）

- 描述轮廓、朝向、相对体量、颜色、发光部位、炮口和其他玩家可见结构。
- 按触发状态说明入场、移动、转向、攻击准备、攻击、受击、部件损毁、整机击毁或离场动画；写清循环、持续和结束后的可见状态。
- 只记录玩家实际可见的画面与动画，不写源文件、Prefab、Clip、帧资源名或制作步骤。
- 可以在本章直接插入能说明当前外观或动画状态的图片。图片遵循项目媒体目录与相对路径规则，每张图附图注；没有有效当前图片时不放占位图。

## 3. 背景故事

- 记录当前项目已经确认、且玩家能够从名称、界面、剧情或其他正式内容中获知的敌机来历、所属势力、制造或作战用途、服役经历和当前任务。
- 只保留与该敌机身份、战斗定位和玩家体验直接相关的设定，不扩写世界观总览，也不把其他敌机的故事并入本文。
- 当前没有可确认的背景故事时，明确写“当前项目未提供该敌机的背景故事”，不得根据外观、名称、行为或策划案自行推断。

## 4. 部件一览

- 列出敌机主体、核心、武器、机翼、机舱等玩家可识别部件；只有一个主体部件时也必须明确写出。
- 对每个可受击或可破坏部件写明当前耐久、能否锁定、受击反馈、生命条、毁坏表现和毁坏后的能力影响。
- 说明多个受击区域是否共享耐久，以及部件毁坏与整机击毁、阶段推进或能力关闭的关系。
- 优先使用表格组织“部件、耐久、可锁定、毁坏影响、玩家反馈”；不写内部组件、字段、任务节点或伤害派发链。

## 5. 攻击方式

- 每种当前已实现的攻击使用独立三级标题或条目说明，不把不同攻击混成一段。
- 按玩家观察顺序写明触发条件、预警、瞄准或锁定、发射位置、攻击轨迹、伤害、持续或连发节奏、恢复时间和结束反馈。
- 写明玩家能否闪避、拦截或打断，以及攻击物与玩家舰体、护盾和我方火力的特殊交互。
- 没有主动攻击时仍保留本章，明确碰撞、阻挡、自毁或其他威胁方式。

## 6. 行动逻辑

- 按时间顺序描述生成入场、首次等待、移动或巡航、停留、攻击选择、循环、追踪、冲撞、撤离和击毁后的完整行为。
- 写明玩家能观察到的速度、范围、路线、间隔、优先级与随机边界，以及始终稳定的行为规律。
- 说明部件毁坏、攻击中断、强制清场或致命状态如何改变当前行动，以及何时失去伤害资格、计入击落或不再阻塞结算。
- 只描述玩家可感知的逻辑结果，不写行为树、Task、Blackboard、System 或内部状态字段。

## 7. 状态转换

- 仅在敌机存在阶段、形态转换或实质能力状态切换时保留本章；没有这类内容时省略整个章节。
- 按“触发条件 → 转换过程 → 玩家反馈 → 新部件/攻击/行动规则 → 可打断与致命边界”描述每次转换。
- 普通受击、短暂动画、纯换色或不改变玩法规则的损毁表现不构成状态转换，不为这些内容保留本章。
