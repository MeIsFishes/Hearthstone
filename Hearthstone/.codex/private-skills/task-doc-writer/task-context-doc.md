# TaskContext 文档说明

TaskContext 文档输出到：AutoDoc/Task/TaskContext/

默认一个 Context 类一篇文档，文件名优先使用 Context 类名。抽象 Context 只有在项目中承载明确共享业务字段时才单独记录。

TaskContext 文档只允许包含以下章节：

1. TaskContext声明
2. 使用场景
3. 字段列表

## 1. TaskContext声明

本章节只记录该 TaskContext 类的全名和包含命名空间的全拓展名。只有存在除 `TaskContextBase` 外的特殊继承关系时，才额外记录继承关系；没有特殊继承关系时不要说明。

## 2. 使用场景

本章节记录该 Context 在什么业务场景下承载 Task 运行输入，侧重游戏功能语义，而不是调用链视角。

必须说明：

- 这个 Context 承载哪类游戏功能的一次 Task 运行输入。
- 它通常代表哪种业务对象、事件、技能、关卡流程、AI 行为或演出过程。
- 配置者或业务逻辑使用该 Context 时，可以依赖哪些业务语义。

不要把重点放在：

- 某个 System、方法名或具体调用链的逐层描述。
- TaskApi 底层创建流程。
- 与该 Context 无关的完整玩法设计。

如果只能确认类定义但无法确认具体游戏功能，应明确写“当前仅能确认该 Context 是预留场景输入，业务场景未在现有代码或配置中明确”，不要猜测。

## 3. 字段列表

本章节记录每个字段的含义。

每个字段一行，写明字段名、类型、含义、逻辑可空性、默认值、取值或留空行为。

字段列表不要记录字段值具体从哪里写入或读取，例如不要写创建方法、System、TaskApi、CSV、Blackboard、上游 Task 或具体调用链这类来源信息。

必须标明字段在逻辑上是否可空。判断标准是该字段在 Context 语义上是否允许省略，而不是字段为空时程序是否会报错。

逻辑可空性写法限定为：

- `不可空`：字段是该 Context 语义成立所必需的运行输入；即使代码存在默认值，也应记录为不可空。
- `可空`：字段省略后 Context 语义仍完整，默认值代表明确的有效行为。
- `条件可空`：字段只在另一个字段、业务模式或运行分支下才允许省略；必须写清条件。

字段说明要求：

- 每个字段都要写清业务含义，不只重复字段名。
- 不要展开字段赋值来源、创建链路或调用链路。
