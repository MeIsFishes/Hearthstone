# Task 节点文档说明

Task 节点文档按代码归属输出：

- `BbxCommon` 命名空间下的底层或通用 Task 节点：`AutoDoc/Task/TaskNode/BbxCommon/`
- 业务命名空间下的 Task 节点：`AutoDoc/Task/TaskNode/`

默认一个节点类一篇文档，文件名优先使用节点类名。条件节点、持续节点和一次性节点也归入本类。

底层节点文档必须单独放在 `BbxCommon/` 子目录，不得与业务节点文档混放。`AutoDoc/Task/TaskNode/` 根目录还必须维护一篇总文档，用于记录每个 Task 节点文档路径、节点类全名、节点类型、用途分类和一句话用途说明。总文档格式见 [Task 节点总文档说明](task-node-index-doc.md)。

Task 节点文档只允许包含以下章节：

1. 节点声明
2. 节点功能
3. 字段列表

## 1. 节点声明

本章节只记录该 Task 类的全名和包含命名空间的全拓展名。只有存在除 Task 底层基类外的特殊继承关系时，才额外记录继承关系；没有特殊继承关系时不要说明。

## 2. 节点功能

本章节记录当前节点在 Task 配置中表达的用户功能语义，优先说明“这个节点能让配置者实现什么效果”。只在理解功能边界必要时补充内部逻辑。

必须聚焦：

- 该节点代表的玩法效果、表现效果、流程控制能力或条件能力。
- 配置者使用该节点时能控制哪些业务语义。
- 节点成功、失败或持续运行对 Task 图语义的影响。

可以记录：

- 这个节点通常用于哪个技能、事件、AI 或 Task 图。
- 未来可能扩展的玩法意图。

上面内容如有倾向则记录，如没有直接留空，不要编造。尽可能一句话说清。

不要记录：

- 逐行代码流程、生命周期钩子调用顺序和纯程序实现细节。
- 调用链、启动入口、场景部署方式。
- BbxCommon Task 底层通用生命周期说明。

如果节点没有自定义逻辑，只继承父类默认行为，应明确写“当前类未实现额外业务逻辑”，不要补充猜测。

## 3. 字段列表

本章节记录每个字段的含义。

每个字段一行，写明字段名、类型、含义、逻辑可空性、默认值、取值或留空行为。

字段列表不要记录字段值具体从哪里读取，例如不要写 `Value`、`Context`、`Blackboard`、CSV 字段或某个 Context 字段名这类来源信息。

必须标明字段在逻辑上是否可空。判断标准是该字段在节点语义上是否允许省略，而不是字段为空时程序是否会报错。

逻辑可空性写法限定为：

- `不可空`：字段是节点语义成立所必需的配置；即使代码存在默认值，也应记录为不可空。
- `可空`：字段省略后节点语义仍完整，默认值代表明确的有效行为。
- `条件可空`：字段只在另一个字段、模式、枚举值或运行分支下才允许省略；必须写清条件。

字段标准模板示例：

- `CompareType`，`ECompare`类型，比较方式；不可空，默认 `Equal`；`Equal` 表示相等，`NotEqual` 表示不相等，`Greater` 表示左值大于右值，`GreaterOrEqual` 表示左值大于等于右值，`Less` 表示左值小于右值，`LessOrEqual` 表示左值小于等于右值。

字段边界要求：

- `bool` 字段必须分别写清 `true` 与 `false` 的行为。
- 数值字段必须写清默认值、允许范围、零值和负值行为。不要替代码增加规则。
- 枚举字段必须写明枚举项代表的含义和行为。
