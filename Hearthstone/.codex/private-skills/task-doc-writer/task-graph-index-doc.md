# Task 图集总文档说明

Task 图集总文档输出到：

```text
AutoDoc/Task/TaskGraph/TaskGraphIndex.md
```

该文档是 `AutoDoc/Task/TaskGraph/` 的目录级索引，用来记录每个 Task 图集文档名、入口 Task 图，以及该图集的外部调用来源。Task 图集文档名不要求和业务场景一一对应；总文档负责说明“这个图集从哪里被启动或配置到”。

Task 图集总文档只允许包含以下章节：

```markdown
# Task 图集总文档

## 1. Task图集索引
```

## 1. Task图集索引

本章节按 Task 图集逐条记录。每一条必须能对应到 `AutoDoc/Task/TaskGraph/` 下的一篇图集文档。

推荐使用表格：

```markdown
| Task图集文档 | 入口Task图 | 调用来源说明 |
| --- | --- | --- |
| `ActiveFireball.md` | `ActiveFireball` | CSV配置：`Skill.csv` / `Id=...` / `EntryTaskName`，... |
| `LevelEvent_001.md` | `LevelEvent_001` | 代码调用：`Assets/Scripts/.../ExampleSystem.cs` / `RunTask(...)`，... |
```

字段要求：

- `Task图集文档`：必须填写图集文档文件名，包含 `.md` 后缀。
- `入口Task图`：填写该图集文档中记录的入口 Task 图名称，通常是 Task 配置文件去掉扩展名后的名称。
- `调用来源说明`：合并记录调用来源类型、来源定位和一句说明；来源类型限定为 `CSV配置`、`代码调用`、`配置引用`、`编辑器配置` 或 `待确认`；来源定位必须写到能让后续维护者找到来源的位置；不要展开图集内部流程。

调用来源定位规则：

- CSV 配置来源必须写清 CSV 文件名、行定位方式、列名或字段名；如果用户或工具能确认具体单元格，优先写具体单元格；说明内容只写该配置项的业务意义，不强调代码调用链路。
- 代码调用来源必须写清代码文件路径、类名或方法名，以及调用 `TaskApi.CreateTask`、`TaskApi.RunTask`、`RunTask` 或等价接口的位置；说明内容可以简短记录调用链路。
- 配置引用来源必须写清引用该 Task key 的配置文件、字段名和字段值。
- 编辑器配置来源必须写清对应 `.editor.json`、`.task.setting` 或其它编辑器配置文件，以及记录 Task key 的字段。
- 如果同一个 Task 图集有多个调用来源，应拆成多行；不要把多个来源挤在同一个单元格里。
- 如果只能确认存在 Task 图集文档，但暂时无法确认调用来源，`调用来源说明` 以 `待确认：` 开头，并写当前已经确认到的最大范围。

维护要求：

- 新增 Task 图集文档时，必须在总文档新增一行。
- 删除或重命名 Task 图集文档时，必须同步更新总文档。
- 入口 Task 图变更时，必须同步更新总文档中的 `入口Task图`。
- 图集内部新增或删除关联图时，通常不需要更新总文档；只有入口图或调用来源变化时才更新。
- 总文档不记录节点字段、Context 字段、图集内部关联图细节；这些内容分别写入对应图集文档、Task 节点文档和 TaskContext 文档。
