# 生成美术资源

依据项目美术文档生成或编辑 2D 图片，检查成品与目标风格的一致性，并把用户确认的长期变化同步到对应文档。

## 约束优先级

按以下顺序解决同一视觉要求的冲突：

1. 当前用户提示词。
2. 目标模块美术文档中的专属规则。
3. 人物、场景或物件分类规格。
4. 美术风格总文档。
5. 项目内参考图片与已有资产。

用户提示词未覆盖的部分继续沿用下级约束。用户明确要求偏离现有文档时，先按用户要求生成或编辑图片，再判断该变化应否写回文档。

## 1. 定位美术文档

1. 始终读取 `AutoDoc/Art/Style/art-style-overview.md`，提取核心风格、形状与线条、整体色彩设计、代表色和对应设计风格。
2. 在 `AutoDoc/Art/Modules/*/*.md` 中按图片主题和用途找到目标模块，读取模块风格、图标规格、参考图片和已有资产列表。
3. 根据模块引用的规格 ID 读取对应分类规格：
   - `CHAR-*`：`AutoDoc/Art/Specifications/character-specifications.md`
   - `SCENE-*`：`AutoDoc/Art/Specifications/scene-specifications.md`
   - `OBJECT-*`：`AutoDoc/Art/Specifications/object-specifications.md`
4. 查看文档引用的项目内样图和与目标最接近的已有资产，确认真实的轮廓、色彩、构图、光照和细节密度。
5. 若没有对应模块或分类规格，以用户提示词和总风格为依据完成当前资产，并在文档修正阶段判断是否需要补充最小范围的文档约束。

## 2. 整理生成要求

把用户提示词与选中的文档约束整理为一份具体的图片要求，至少明确：

- 主体、用途和视觉重点。
- 画布尺寸、宽高比、主体占比和安全区。
- 形状、轮廓、线条和细节密度。
- 整体色彩关系、代表色、材质、光照和氛围。
- 视角、朝向、构图和背景或 Alpha 要求。
- 需要保留的元素、允许变化的元素和所需视觉变体。

只把与当前图片有关的约束写入生成提示，不机械堆叠整份文档。对用户已经明确指定的内容使用确定表达，对未指定内容使用文档中的默认规则。

## 3. 生成或编辑图片

1. 新建图片时，使用整理后的要求直接生成；需要继承现有设计时，把最相关的项目样图作为视觉参考。
2. 编辑图片时，把待修改原图作为输入，明确列出必须保留和必须修改的部分。一次编辑聚焦一组相互关联的变化。
3. 输出到目标模块的美术资源目录，沿用同目录命名方式和图片格式。
4. 生成后实际查看输出图片，不根据提示词或工具返回文字推断成品效果。

### 多资产并行生成

当本次需要生成的资产达到 3 张或以上时，允许主代理使用 subagent 按资产分别生成：

1. 为每个 subagent 明确分配独立的资产、生成要求和输出路径，避免多个代理修改同一文件。
2. 要求 subagent 在完成后把生成结果和实际文件路径返回主代理，不得只汇报生成状态。
3. 主代理必须实际查看并统一评审所有返回结果；需要迭代时，将对应资产交回原 subagent 或由主代理继续处理。
4. 主代理必须在自己的对话输出中逐张展示最终生成结果，不得只提供路径、文字摘要或依赖 subagent 的消息展示。

## 4. 按风格评审并迭代

先检查用户提示词的明确要求，再检查对应文档中的其余约束：

1. 主体、数量、姿态、朝向和用途是否正确。
2. 轮廓、线条、比例和细节密度是否属于目标风格。
3. 整体色彩关系、代表色、明暗、材质和光照是否一致。
4. 构图、画布比例、安全区、背景和透明区域是否符合规格。
5. 与同模块资产并列时，识别度、层级和系列一致性是否成立。

构图和主体正确、仅局部视觉不符时，基于当前成品继续编辑，并在提示中固定需保留内容。主体结构或整体方向错误时，修正生成要求后重新生成。每轮都重新查看成品，直到满足用户提示词和未被覆盖的文档约束，或明确说明仍无法消除的差异。

## 5. 修正美术文档

仅在需要新增或修改美术文档时，读取并遵循 `$art-doc-writer`。根据用户提示词表达的适用范围选择修改位置：

- 项目长期共享的风格变化：修改美术风格总文档。
- 只适用于某组界面或主题图片的变化：修改对应模块美术文档。
- 适用于一类人物、场景或物件的生成规格：修改对应分类规格文档。
- 只适用于当前单张图片的特殊要求：保留为本次资产的特例，不扩大为全局或分类规则。

用户明确要求更新规则时按其指定范围修改。范围没有明确说明时，选择能够准确容纳当前变化的最小文档范围，不因单个成品自动改变全局风格。

资产落盘后，在对应模块的“目前已有资产列表”中记录文件名、项目内路径、图片内容与用途、实际尺寸和格式。文档已有错误或与用户确认的新方向冲突时，修正原规则，避免同时保留互相矛盾的描述。

## 6. 最终检查

- 确认图片文件位于预期路径，尺寸、格式和透明区域正确。
- 复查成品是否优先满足用户提示词，并满足其余适用文档约束。
- 生成 3 张或以上资产并使用 subagent 时，确认主代理已收到、查看并逐张展示全部最终结果。
- 确认新增或修改的文档符合固定格式，规格 ID 和模块引用一致。
- 汇报生成或编辑的资产路径、采用的文档、主要视觉判断、迭代结果和文档改动。
