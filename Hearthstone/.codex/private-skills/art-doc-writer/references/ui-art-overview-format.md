# UI 美术文档格式

UI 美术文档固定保存为 `AutoDoc/Art/UI/ui-art-overview.md`。

本文档只记录 2D 图片美术范围内的 UI 信息。界面交互、程序组件、数据绑定和业务流程不写入本文档。

## 固定结构

严格按下列章节名称和顺序编写：

```markdown
# <项目名> UI 美术文档

## 1. 文档范围

## 2. UI 通用资产分组

## 3. 当前主要 UI 界面

## 4. UI 美术资产缺失
```

暂时无法填写的章节保留标题，并明确写出缺少的确认信息；不要用推测内容补全。第 4 章确认没有缺失资产时，只保留章节标题，标题下留空。

## 章节内容

### 1. 文档范围

说明本文档覆盖哪些 UI 美术内容、主要界面的判定范围以及本次信息来源。固定明确以下职责边界：

- 项目级 UI 形状、线条、色彩和纹理规则以美术风格总文档为准。
- 单一主题或模块专属图片的详细生成规格以对应模块美术文档为准。
- 本文档按美术风格集中维护跨界面复用的通用 2D 图片资产分组，以及当前主要界面的视觉构成和分组归属。

### 2. UI 通用资产分组

根据 UI 美术风格把通用资产划分为若干组。形状、线条、色彩、纹理和装饰语言均一致的通用资产属于同一组；只有存在需要长期分别维护的稳定风格差异时才新建分组。若项目 UI 风格统一，本章节只能有一个分组。

每个分组使用稳定且唯一的分组 ID，格式为 `UI-STYLE-001`、`UI-STYLE-002`，供主要界面和模块美术文档引用。已有分组不得因排序变化而更换 ID；分组停用后不得把原 ID 分配给其他风格。

每个分组严格使用以下结构，可按分组数量连续编号：

```markdown
### 2.<序号> <分组 ID> <分组名称>

**风格说明**：<形状、线条、色彩、纹理和装饰特征>

**适用范围**：<适用的界面、模式或主题范围>

| 资产或资产组 | 类型 | 通用用途 | 项目内路径 | 尺寸 / 格式 | 状态与视觉变体 | 复用约束 |
| --- | --- | --- | --- | --- | --- | --- |
| <名称> | <面板、按钮、边框等> | <适用界面或区域> | <实际相对路径> | <宽 × 高 px / PNG 等> | <普通、悬停、按下、禁用等> | <缩放、九宫格、配色或不可变形区域> |
```

通用资产表只记录已确认存在的 2D 图片。同一资产存在多个状态或成套变体时合并为一个资产组，并在“状态与视觉变体”中列全。只属于一个界面的图片不放入通用资产分组，改在对应主要界面或模块美术文档中记录。

### 3. 当前主要 UI 界面

列出项目目前保留且承担主要玩家操作或信息展示的界面。已经删除的历史界面不保留在表中；尚未落地的计划界面不得写成当前界面。

| 界面名称 | 界面用途 | 主要视觉区域 | UI 风格分组 ID | 使用的通用资产 | 专属美术资产及路径 |
| --- | --- | --- | --- | --- | --- |
| <名称> | <玩家在此查看或完成什么> | <背景、主面板、导航、内容区等> | <UI-STYLE-001> | <引用 §2 对应分组中的资产或资产组> | <已确认存在的名称与相对路径；没有则写“—”> |

“主要视觉区域”描述界面的美术构成，不展开控件回调、页面跳转、数据来源或程序层级。同一界面使用多个 UI 风格分组时逐个列出，并说明各分组对应的视觉区域。

### 4. UI 美术资产缺失

只列出当前代码、Prefab 或配置已经引用，但项目内实际文件缺失的 2D 图片资产。缺失资产必须关联适用的 UI 风格分组并注明现有引用证据；不得把计划新增、未来可能需要或尚未落地的资产写入本章节。

| 资产或资产组 | UI 风格分组 ID | 影响界面或范围 | 缺失内容 | 当前引用证据 | 当前引用路径 |
| --- | --- | --- | --- | --- | --- |
| <名称> | <UI-STYLE-001> | <通用用途或主要界面> | <缺少的图片、状态或变体> | <代码、Prefab 或配置中的实际引用> | <当前引用的相对路径> |

确认没有缺失资产时，本章节标题下留空，不写“无”“暂无”或空表格。资产生成并确认实际文件后，从本章节移除对应条目，并补充到 §2 的通用资产分组或 §3 的主要界面中。
